# Streamers Battle — Draft (Random Draft + Captains Mode)

Онлайн-платформа драфта для Dota 2: случайный пул из 45 героев, баны и пики
как в Captains Mode. Роли — капитан Radiant, капитан Dire, наблюдатель.
Синхронизация между всеми участниками в реальном времени через Firebase.

---

## 1. Что понадобится

- **Node.js 18+** — https://nodejs.org (поставьте LTS).
- Бесплатный аккаунт **Firebase** (Google) и бесплатный аккаунт **Vercel** (или Netlify).

Проверьте, что Node установлен: в терминале `node -v` должно показать версию.

---

## 2. Настройка Firebase (бэкенд, бесплатно)

1. Откройте https://console.firebase.google.com → **Add project** → задайте имя → создайте
   (Google Analytics можно отключить).
2. В левом меню: **Build → Realtime Database → Create Database**.
   - Выберите ближайший регион (например, europe-west1).
   - На выбор режима правил выберите **Start in locked mode** (правила зададим ниже).
3. Вкладка **Rules** этой базы — вставьте правила и нажмите **Publish**.

   **Вариант A — быстрый (без входа, для дружеского турнира):**
   ```json
   {
     "rules": {
       "matches": {
         ".read": true,
         ".write": true
       }
     }
   }
   ```

   **Вариант B — рекомендуемый (требует анонимный вход, защищает от посторонних записей):**
   ```json
   {
     "rules": {
       "matches": {
         ".read": "auth != null",
         ".write": "auth != null"
       }
     }
   }
   ```
   Для варианта B дополнительно включите вход: **Build → Authentication → Get started →
   Sign-in method → Anonymous → Enable**. Приложение само выполняет анонимный вход.

4. Получите конфиг: значок шестерёнки **Project settings → General →
   Your apps → Web (`</>`) → Register app** → скопируйте значения из блока `firebaseConfig`.

---

## 3. Локальный запуск

1. Распакуйте архив, откройте папку в терминале.
2. Установите зависимости:
   ```
   npm install
   ```
3. Создайте файл `.env` (скопируйте из `.env.example`) и впишите значения из Firebase:
   ```
   VITE_FIREBASE_API_KEY=...
   VITE_FIREBASE_AUTH_DOMAIN=ваш-проект.firebaseapp.com
   VITE_FIREBASE_DATABASE_URL=https://ваш-проект-default-rtdb.europe-west1.firebasedatabase.app
   VITE_FIREBASE_PROJECT_ID=ваш-проект
   VITE_FIREBASE_APP_ID=1:...:web:...
   ```
   (`databaseURL` возьмите со страницы Realtime Database — это адрес вида
   `https://...firebasedatabase.app`.)
4. Запустите:
   ```
   npm run dev
   ```
   Откройте показанный адрес (обычно http://localhost:5173). Проверьте драфт
   в двух вкладках/на двух устройствах.

---

## 4. Публикация в интернет (Vercel — проще всего)

1. Залейте проект на GitHub (новый репозиторий). Файл `.env` НЕ попадёт в репозиторий
   (он в `.gitignore`) — это правильно.
2. Зайдите на https://vercel.com → **Add New → Project** → импортируйте репозиторий.
3. Vercel сам определит Vite. Настройки по умолчанию подходят:
   - Build Command: `npm run build`
   - Output Directory: `dist`
4. Откройте **Settings → Environment Variables** и добавьте те же 5 переменных
   (`VITE_FIREBASE_...`) с вашими значениями.
5. Нажмите **Deploy**. Через минуту получите публичный адрес вида
   `https://ваш-проект.vercel.app` — это и есть ссылка для участников.

**Свой домен:** Vercel → Settings → Domains → добавьте домен и пропишите DNS по инструкции.

> Netlify — аналогично: New site from Git → Build `npm run build`, Publish `dist`,
> добавьте те же переменные окружения в Site settings → Environment variables.

Важно: после изменения переменных окружения нужно заново нажать **Redeploy**.

---

## 5. Как проходит турнир

1. Организатор открывает сайт → **Создать матч** → задаёт команды, число банов/пиков,
   таймер и три пароля. Появятся **код комнаты** и **три пароля**.
2. Раздайте каждому: адрес сайта + код комнаты + роль + пароль.
3. Все входят: **Войти в матч** → код → роль → пароль.
4. Когда все на месте — капитан жмёт **Начать драфт** (с этого момента идёт таймер).

Пул из 45 героев и порядок бан/пик задаются при создании и одинаковы у всех.
Ходы синхронизируются мгновенно; одновременный «двойной пик» исключён транзакцией.

## Заметки по безопасности

- Пароли ролей хранятся в базе в открытом виде — это лёгкая защита «чтобы не зайти
  не туда», а не серьёзная криптозащита. Не используйте важные пароли.
- Ключ `apiKey` Firebase — не секрет, его безопасно держать в клиенте; доступ
  ограничивают именно правила базы (раздел 2, п. 3).
- Для более строгой защиты используйте Вариант B правил (анонимный вход).
